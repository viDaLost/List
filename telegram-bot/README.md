# Бот Листа — Telegram Serverless

Бот работает непосредственно на Serverless Telegram. VPS и отдельный Bot API token не нужны. Публичный редактор и статьи находятся на https://list.vitaledanilov.workers.dev. AI-сервисы не используются.

## Как работает доступ

- `/start` создаёт отдельного автора по `message.from.id`, полученному от платформы Telegram. ID не показывается в статьях или сообщениях.
- «Мои статьи» показывает все собственные черновики и публикации с пагинацией. Название открывает редактор; «Предпросмотр» — чтение.
- «Новая статья» открывает Mini App с редактором. Черновик автоматически сохраняется после паузы в наборе текста.
- «Удалить статью» предлагает собственные статьи, затем запрашивает подтверждение. Проверяются владелец и версия; сохраняется резервная копия.
- `/articles`, `/new`, `/delete` дублируют кнопки.

Mini App проверяет Ed25519-подпись `Telegram.WebApp.initData` по официальному production-ключу Telegram и ID подключённого бота. Переданный клиентом ID не используется для входа. `auth_date`, дубликаты полей и бот-отправитель проверяются. Для проверки подписи Bot API token не требуется.

В Telegram и обычном браузере разные cookies и владельцы. Safari/Chrome не получают Telegram-доступ и не переносят свои статьи в Telegram. Браузерный доступ сохраняется только в том же браузере, пока сохранены данные сайта. Нет пользовательских кодов привязки, экспорта ключей, логина или пароля.

SQLite Telegram хранит настройки бота и служебную связь пользователя с автором. Тексты, изображения, черновики и резервные копии хранятся в Cloudflare D1. ID не включён в публичную модель статьи.

## Подключение или обновление владельцем с телефона

1. BotFather → отдельный бот → Serverless → CLI Access → Access token.
2. На сайте с доступом владельца откройте `/_list/telegram`.
3. Вставьте CLI-токен `app…:…`. Сервер обновит только распознанную версию Листа, применит безопасные миграции, проверит таблицы, сохранение настроек и webhook для `message` и `callback_query`.
4. Откройте бота и отправьте `/start`. Пользователям токены не нужны.

CLI-токен используется только в запросе по HTTPS, не сохраняется и не попадает в репозиторий. Он нужен владельцу для публикации кода, а не для доступа пользователей. Настройка выполняется через временный приватный wrapper management API; публичного setup endpoint нет. Публикация кода GitHub сама по себе не обновляет уже запущенный бот.

## CLI

Из этого каталога: `npx --package=@tgcloud/cli@0.2.0 tgcloud login`, `npm run deploy`, `npm run migrate`. Миграции применяют только безопасные изменения. `.tgcloud/` исключён из git.

Официальная документация: https://core.telegram.org/bots/serverless и https://core.telegram.org/bots/webapps#validating-data-for-third-party-use.

## Instant View

В `instant-view.rules` находится шаблон для публичных статей Листа. Его нужно проверить и сохранить в редакторе https://instantview.telegram.org/. Специальная ссылка `https://t.me/iv?url=URL&rhash=HASH` работает с сохранённым шаблоном. Для появления стандартной кнопки у обычных ссылок Telegram должен одобрить шаблон. Оформление цветов, интерактивные чек-листы и авторские кнопки в Instant View могут отличаться: для полного оформления открывайте оригинал.
