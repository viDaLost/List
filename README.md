# Лист

Мобильный сервис публикации статей: собственные адреса, оформление и карточки ссылок для мессенджеров.

- Редактор с текстом, заголовками, изображениями, цитатами, кнопками, чек-листами и раскрывающимися пояснениями.
- Краткая версия «Суть за минуту», оглавление и постоянные ссылки на разделы.
- Личные заметки читателя, отметки чек-листов и возврат к месту чтения в браузере.
- Чтение и публикация без регистрации, логина, пароля, ChatGPT или Claude. Браузерный доступ сохраняется в защищённой cookie; Telegram использует отдельное пространство по подтверждённому ID.
- Цвет каждого блока, общий фон, произвольная подпись в конце и до пяти кнопок в ряд. Публикация — внизу редактора.
- Перетаскивание блоков за постоянно видимую ручку на телефоне и компьютере, подсветка места вставки и автоматическая прокрутка. Стрелки клавиатуры на ручке также меняют порядок; Escape отменяет перенос.
- Жалобы, модерация, ограничения частоты действий и последние десять резервных версий каждой статьи.

## Работающий сервис

https://list.vitaledanilov.workers.dev

Основной сервер размещён в аккаунте владельца на **Cloudflare Workers**, база — **Cloudflare D1** (`list-articles`). Изображения и приватные резервные версии хранятся в D1 частями; R2 в этом аккаунте не активирован. При подключении R2 приложение может использовать его вместо D1. Общий предел встроенного хранилища — 256 МБ в кодировке base64; при заполнении новые записи отклоняются, существующие данные не стираются.

Предел объектного хранилища соответствует примерно 192 МиБ исходных файлов на весь сервис, включая резервные версии. Это ограничение триггера `object_chunks_quota` в рабочей D1, а не объём оперативной памяти Worker. Десять предыдущих версий каждой статьи тоже занимают место. Пределы Workers и D1 зависят от тарифа аккаунта; число HTTP-запросов не равно числу читателей.

Доступ в обычном браузере хранится в защищённой cookie. Очистка данных сайта может лишить доступа; перенос пользовательских ключей не предусмотрен. Telegram-статьи доступны через бота независимо от браузерного пространства.

Бот Telegram Serverless открывает меню собственных статей, редактор Mini App и удаление с подтверждением. Telegram ID берётся из доверенных событий платформы и проверяется в Mini App по Ed25519-подписи Telegram. Telegram и обычный браузер используют разные cookies и владельцев, без пользовательских ключей привязки. Для первоначальной публикации или обновления кода владелец один раз вводит CLI-токен в закрытой форме `/_list/telegram`; он не сохраняется. Подробности — в `telegram-bot/README.md`.

Панель владельца: `/_list/admin`. Права проверяются по серверной записи автора, а не по данным, присланным из браузера. Первоначальный доступ владельца выдаётся отдельной одноразовой ссылкой. Секреты и пользовательские данные в репозиторий не входят.

## Разработка и проверки

Требуется Node.js 24 или новее и pnpm.

~~~sh
pnpm install --frozen-lockfile
pnpm exec tsc --noEmit
node --test tests/api.test.mjs
pnpm run build
~~~

Приложение использует React, Vinext и Cloudflare Workers. Конфигурация D1/R2 находится в .openai/hosting.json; схема и последовательные миграции — в db/schema.ts и drizzle/.

Миграции уже опубликованных версий изменять нельзя: новые изменения добавляются отдельной миграцией. База для локальной разработки отделена от рабочей базы.

## Размещение и обновления Cloudflare

В подключённом аккаунте используются Worker `list` и D1 `list-articles`. Обычная публикация через Wrangler:

~~~sh
pnpm install --frozen-lockfile
pnpm run build:cloudflare
pnpm exec wrangler d1 migrations apply DB --remote --config dist/server/wrangler.json
pnpm exec wrangler deploy --config dist/server/wrangler.json
~~~

Команды требуют вашей авторизации Wrangler. `TELEGRAM_BRIDGE_SECRET` хранится как секрет Worker и в приватных настройках Telegram Serverless. При обновлении сохраняйте его. Он нужен только для связи с ботом; вход через сторонние AI-сервисы отсутствует.

`build:cloudflare` формирует конфигурацию с настоящими D1 и Workers.dev адресами этого проекта. При переносе в другой аккаунт обновите account ID, database ID, имя Worker и публичный адрес в сборочных файлах, настройте адрес бота и секреты. Полный набор миграций находится в `drizzle/`; уже применённые миграции изменять нельзя.

Первый запуск через подключение Cloudflare использует воспроизводимый пакет `scripts/package-cloudflare-api.mjs`: статические файлы включены в Worker. Поэтому запросы к ним учитываются как вызовы Worker. Последующие публикации Wrangler используют штатные Static Assets. Автоматическое развёртывание из GitHub пока не настроено: изменения в `main` сами по себе не обновляют сервер.

## Данные и восстановление

Публикации и черновики находятся в D1. Перед изменением, удалением или модерацией предыдущая версия статьи записывается в приватное объектное хранилище (D1 или R2). Панель владельца позволяет скачать резервную версию и восстановить её как черновик исходного автора. Хранятся последние десять версий каждой статьи.

Заметки, отметки чек-листов и место чтения хранятся только в браузере читателя и не синхронизируются с сервером.

## Проверки

Тесты выполняют реальные обработчики API с SQLite и тестовым адаптером объектного хранилища: проверяют изоляцию авторов, анонимное чтение, адреса и перенаправления, безопасный вывод, ограничения запросов, жалобы, модерацию, резервирование и восстановление.
